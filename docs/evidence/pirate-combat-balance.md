# Pirate combat balance — PR1

Generated 48,600 seeded battles across 162 matchups; 300 runs per matchup.
Seed corpus: `asterion-pirate-combat-v2`. Primary-matchup seed fields only: faction, score band, attacker tech, formation, and run index. The Ripper calibration uses a separate seed schema: `pirate-combat-v2:double-attack:<base-10 zero-padded 4-digit run index>` (no matchup fields).

## Scope and limits

This is an internal Asterion calibration. It checks pirate ship statistics, the shared six-class matchup table, population-share profile sampling, and the once-per-round Ripper ability. It does not establish Nemexia parity. It does not simulate contact frequency, travel, incoming raids, planet siege, or planet destruction; those belong to later PRs.
Each player fleet targets 10,000 combat population; actual opening player-fleet population across primary matchups ranged from 9,972 to 10,027 because ships use whole counts. A pirate profile targets 90–95% of that amount (9,000–9,500): the same seeded coefficient as production for a fresh owner (adaptive Q = 0). It rounds to whole ships using the profile population shares. Shares mean population percentages, not percentages of ship count. Every generated profile is built from 20 seeded population slices of 5% each; each slice first samples a tier using the existing score-based tier weights, then chooses a ship class uniformly at random within that tier. Player and pirate ship levels and pirate technology stay derived from resource points; player technology is independently checked at levels 0, 5, and 10. Main matchups and the separate Potroshitel calibration each allow up to 12 rounds per battle.
Independent sample counts: 48,600 primary battles (162 matchups × 300 seeds each); 2,000 separate Ripper calibration battles; 21 level/technology stat snapshots; 21 source-faction catalog stat snapshots summarized into 7 pirate medians.
Across primary matchups, the largest observed absolute error from the seeded pirate population target was 19 population points. The budget helper rounds each eligible class allocation to whole ships; the observed error is reported instead of claiming a tighter universal bound.
