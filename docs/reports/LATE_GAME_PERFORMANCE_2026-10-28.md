# Производительность поздней игры — отчёт (28–29.10.2026)

PR: ratoker-jpg/Asterion#116 (ветка `claude/late-game-performance`). Сырые цифры — `LATE_GAME_PERFORMANCE_2026-10-28.json` рядом.

## Коротко

- **Прогон отсутствия больше не замораживает игру.** Он идёт в Web Worker: во время прогона
  интерфейс держит ~59 FPS (на main — 1,8 FPS, кадры по 0,7–1,2 с).
- **Прогон в 2,4–3,6 раза быстрее** на позднем мире (в игре 1 ч отсутствия на мире дня 1:
  123 с → 52 с; в Node: 259 с → 73 с).
- **FPS в простое на позднем мире ровный.** Мир дня 1, после прогона: на main 35–40 FPS,
  p95 кадра 83–100 мс, ~2 длинные задачи по ~300 мс в секунду на каждом экране; на ветке 56–60 FPS,
  p95 16,8 мс.
- **Прогон стал детерминированным:** один мир при любой нарезке, через воркер и после
  сохранения/загрузки посередине. Красные long-horizon проверки main проходят (176/176 локально).
- **Найден и исправлен скрытый риск сохранений:** пиратский профиль, созданный другим JS-движком,
  делал сохранение «повреждённым» (см. ниже).
- **Цель «24 ч на мире дня 7 за 1–2 минуты» не достигнута.** День 1 → день 2 (24 ч) — 58 минут.
  Что осталось и почему — в последнем разделе.

## Как мерили

- Машина: AMD Ryzen 5 5600 (6/12), 17 ГБ, Windows 10, Node 24.16, Electron 44. Параллельно шла генерация
  фикстур (один поток), поэтому цифры немного шумят.
- Фикстуры: `npm run benchmark:late-game -- generate` — полный мир (10 галактик, 100 NPC, астероиды,
  разведка, пираты), который NPC сами прожили N игровых дней с 01.01.2026. День 1 — 18,9 МБ,
  день 2 — 39,9 МБ. В репозиторий не кладутся (генератор в `tools/late-game-catchup.mjs`).
  Генерируются кодом ветки; main загружает их после переноса одного исправления загрузки (см. ниже) —
  только для замера «до».
- «До» — main da25bba; «после» — эта ветка. В игре: `electron/late-game-fps-qa.cjs` (окно не показывается:
  рендер вне экрана, 60 FPS), часы страницы сдвинуты так, что курсор прогона на H часов позади «сейчас».
  Сохранение не меняется.
- Помимо rAF-кадров считается разрыв 16-мс таймера — сколько был занят UI-поток.

## Сохранение

| Мир | Размер | `JSON.stringify` |
|---|---|---|
| День 0 | 0,3 МБ | 2 мс |
| День 1 | 18,9 МБ | 88 мс |
| День 2 | 39,9 МБ | 192 мс |

На main весь мир сериализовался на **каждом** тике (раз в секунду) — на дне 2 это ~200 мс каждую
секунду, главная причина просадки FPS. На ветке тик пишется не чаще, чем раз в 50× стоимости записи
(≤ ~2% UI-потока, не реже раза в 10 с), команды игрока — сразу, при закрытии окна — сброс. Прогон в воркере
сохраняет прогресс раз в 15 с (сериализация в воркере).

## Что было медленным и что сделано

1. **Прогон в UI-потоке** (задачи по 40 мс, после каждой — перерисовка всего App и автосейв мира раз
   в 2 с) → Web Worker (`src/npc-catchup.worker.ts`, `application/npc-catchup-runner.ts`): куски ~250 мс,
   прогресс через маленький стор (перерисовывается только окно прогресса), в конце App берёт только
   изменённые прогоном поля; без воркера или при ошибке — прежний путь.
2. **Досчёт всех владельцев на каждом прилёте флота** (в поздней игре почти все 100) → только владельцы,
   которых касаются полёты этой точки.
3. **Повторные полные проходы на каждое событие** → индексы и кэши: следующий момент планеты,
   планеты по владельцу, очки владельца (по читаемым полям), системы для решений NPC (по видимым
   временным объектам), карта для кандидатов миссий, отпечаток систем для рейдов, архив полётов,
   помощь по запросам, ранний выход для пиратского контакта, выбор следующего полёта за один проход,
   текст отказа атаки только при чтении.
4. **Расписание временных объектов вселенной с 01.01.2026** (~7 000 циклов на систему и вид к концу 2026,
   ~1 ГБ кучи; в UI-потоке и снова в воркере) → типизированные массивы (~0,1 ГБ вне кучи), построение
   в простое (`requestIdleCallback`).
5. **Автосейв каждого тика** → бюджет ~2% (см. выше).
6. **Экран боевых докладов** перечитывал и разбирал всё сохранение из localStorage каждую секунду →
   берёт опубликованное состояние.

Поведение не меняется: каждая оптимизация сверена побайтным дайджестом (полный мир 6 ч `8ce7cafe…`;
мир дня 1 + 30 мин против эталона после исправлений детерминизма, коммит 4f6e30b, `cb6df959…`).
Регрессия — `src/application/npc-catchup-slicing.test.ts` (в `test:npc`): побайтно один мир при кусках
64 / 100 000 групп и через раннер воркера, физически тот же после загрузки между кусками, бюджет
90 с на 3 ч полного мира (локально ~8 с). FPS — `npm run test:late-game-fps-ui` в CI (шард npc-replay,
CPU-рендер, бюджет p95 150 мс).

## Детерминизм (красные CI-задачи main)

Причины расхождений и исправления:
- после боя оставались записи командиров с `count: 0` и старым уровнем (загрузка их выбрасывала);
- повторный шпионский отчёт NPC читал ресурсы цели, досчитанные до границы куска → цель досчитывается
  на момент решения;
- журнал разведки рос без предела, загрузка оставляла 256 → та же граница в рантайме;
- порядок ключей рекордов разведки зависел от нарезки → порядок по id;
- квитанции улучшений космодрома NPC жили в окне 256, остальные действия — 64 → общее окно 64;
- блокировка перенаселения снималась в момент очередного досчёта → в точный момент сжигания, он же —
  контрольная точка прогона;
- окно сводки мира заменялось «неполной» сводкой короткого хвоста прогона (full-world Electron QA).

Итоговые миры отличаются от main ровно этими исправлениями; правила и поведение NPC те же.
`test:header-ui` падал из-за гонки в самом тесте (ресурсы растут за время перезагрузки) — допуск роста 0,01%.

## Найденный риск сохранений (исправлен)

При загрузке профиль пирата пересоздаётся из сида и сравнивается с сохранённым побайтно. Ожидаемые доли
тиров считаются через `Math.pow/exp`, а их последний бит различается между движками: Node 24 даёт
82.27063208603401, Electron 44 — 82.270632086034. Из-за этого сохранение, где пиратский профиль создан
другим движком, открывалось как «Сохранение повреждено: Повреждены очереди или полёты автономного NPC».
Так же сломались бы сохранения всех игроков, если обновление Electron изменит математику V8. Теперь доли
сравниваются до 12 значащих цифр; выборка, тир и корабли — по-прежнему точно (`contact.ts`, тест в
`contact.test.ts`).

## Не сделано и почему

- **24 ч на мире дня 7 за 1–2 мин — нет.** На дне 1–2 прогон даёт ~25 игровых минут в минуту
  (24 ч ≈ 58 мин), к дню 7 медленнее. Профиль поздней игры после всех правок: ~50% — решения NPC
  (`applyNpcAutonomyAttention`: кандидаты миссий ~18%, контекст полезности ~7%, помощь и пираты ~8%),
  ~13% — `reconcileFlights` (проход по ~2 000 живым полётам на каждое событие), ~12% — архив истории.
  Остальное размазано по сотням функций. Дальше нужны структурные шаги, которые трогают модель решений:
  инкрементальная очередь полётов по времени события и удешевление одного «взгляда» NPC (кандидаты
  по семействам, общий контекст на момент). Параллелить нельзя: решения владельцев в одну
  миллисекунду меняют общее состояние по очереди.
- **Замеры на мирах дня 3 и 7.** Генерация идёт ~1 игровой час за 3–4 минуты; день 3 появится
  примерно через час после отчёта, день 7 — через много часов. Генератор продолжает с готовой
  фикстуры (`--from`).
- **CSS-эффекты (blur, backdrop-filter)** не трогал: на GPU это не узкое место (ровно 60/120 FPS на всех
  экранах после правок UI-потока).
- **Остаток длинных задач в простое на ветке** (3–5 за 8 с, до 100 мс, на «Командовании» 261 мс):
  это тик сверки живого мира и редкий автосейв. Не разбирал.
