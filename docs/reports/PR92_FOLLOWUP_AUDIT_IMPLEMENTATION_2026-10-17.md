## Fixed — player-visible

1. **Normal Attack → occupied unique/anomaly** (`src/application/flights.ts`, `src/application/exploration-combat.ts`, `src/App.tsx`, `src/OperationsView.tsx`, `src/FleetWorkspacePortal.tsx`): Attack is validated against the actual persisted contact cycle and foreign occupancy, requires a selected real fleet, uses the production `resolveCombat` with actual launch snapshots and seeded report ID, applies surviving ship/commander losses and updates the claim. An attacker only takes occupancy when it wins and has surviving combatants. A defending ship or commander retains a draw/defense; if neither side has survivors, the claim is released and undelivered cargo is destroyed, without a draw capture. Attack win captures cargo by `settleExplorationContest` (30% of accumulated material constrained by surviving cargo capacity) and keeps winner on orbit. Attackers can recall via the existing 30-second orbit-return procedure. Physical returns and reporting are not instantaneous.
2. **Bot 01 demonstration** (`src/application/exploration-bot01.ts`, `src/App.tsx`, `src/FleetWorkspacePortal.tsx`, `src/OperationsView.tsx`): Test Mode can launch a **finite snapshot from Bot 01's actual planet fleet** into a timed free contact. The ship quantity is reserved from the original NPC planet, the flight has an actual origin/route/arrival, is persisted, can occupy only on arrival, and restores **surviving** hulls exactly once when returning. Two entrypoints: `Флоты → BOT 01 · ЗАХВАТИТЬ ОБЪЕКТ (ТЕСТ)` auto-selects a free live contact; or the selected free dossier in `Операции → ТЕСТ: BOT 01 · ЗАНЯТЬ ОБЪЕКТ`. After arrival accept/select the occupied contact and launch Attack with player's actual fleet. The outcome is produced only by the existing combat resolver.

Never present hidden foreign NPC mining cargo in Operations before/after recon. Bot 01 is named in the battle report, rather than showing a raw owner ID.

## Deferred scope and limitations

1. **Automatic Production NPC attacks are deliberately deferred by the owner.** The new-game Production save has no real persisted NPC settlement/fleet source. Per the owner's decision, the code keeps a no-source provider: there are no automatic NPC attacks and no fabricated NPC planets, economy, armies, or fleets. The real-source Bot 01 capture/loss/report scenario remains Test Mode only. The source-provider boundary is ready to accept real sources later while keeping the combat and settlement resolver reusable. Do not claim automatic NPC attacks are implemented.
2. The shared reserve uses the existing `EXPLORATION_RULES.resourcePointsBase` baseline when a contact is materialized, independent of the observer's personal score. Replays and visitors therefore use the same finite reserve; this follow-up does not change that baseline or its coefficients (`src/domain/exploration/ledger.ts:116–138`).
3. Combat integration tests use the **real resolver** for ordinary fleet outcomes and commander-only draws; another deterministic scenario covers mutual annihilation, save/reload, and a third contender. Production NPC offense remains deferred by owner decision and is intentionally not simulated.
4. Current anomaly hazard outcome is **cargo loss only**, not ship destruction; each triggered event burns at most 10% of then-stored cargo. Additional hazard effects were not requested or implemented.
5. The late-game economy note is scenario analysis, with the missing fleet, storage, and combat inputs called out; it changes no balance coefficients. It is not a universal profit recommendation.

**Unchanged**: rare-reward single payout event, 30-second recall protocol, storage overflow treatment, deterministic deposits, and the user's exclusive right to merge.
