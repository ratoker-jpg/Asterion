# Интеллект NPC: серия раундов и личности — отчёт (этап G, 01.11.2026)

Основание: ADR `NPC_INTELLIGENCE_ADR_2026-10-31.md` §6.4 и §9.2, решения владельца 1–3, видение §3.2 и §8.1.

## Что теперь умеет игра

После Врат в окне итога появилась кнопка **«Новый раунд»**. Она открывает мастер новой игры с включённой галочкой
**«Продолжить серию»**: тот же командир (ник можно сменить), те же настройки мира, новый сид. В новом мире играют те же
личности NPC под другими никами и на других местах. Они помнят опыт и отношения, но не знают ни одной новой планеты.

- Без галочки — чистая популяция, чужой опыт в неё не попадает. В обычной «Новой игре» галочка выключена.
- В браузерной версии галочка недоступна, причина написана прямо в мастере: «опыт серии хранится только на ПК».
- Если файл опыта повреждён или записан более новой версией игры, причина тоже написана, файл не трогается.
- В меню паузы кампании серии есть **«Закончить раунд серии»** (с подтверждением) — это выход из раунда без Врат.
- Первая завершённая кампания сама основывает серию из своих NPC, поэтому продолжить можно уже после первых Врат.

## Как устроено

**Файлы в профиле игры на ПК** (`electron/persona-file.cjs`, IPC в `electron/save-store.cjs`):

| Файл | Назначение |
|---|---|
| `personas.v1.json` | реестр: до 6 серий, в каждой до 100 личностей |
| `personas.v1.backup.json` | предыдущая версия |
| `personas.v1.damaged.json` | непрочитанный файл, отложенный перед записью; хорошая копия остаётся |

Запись атомарная: временный файл, fsync, rename. Файл более новой версии не перезаписывается.

**Отступление от эскиза ADR.** ADR предлагал хранить `bindings` (`ownerId → personaId`) в сохранении. Сделано иначе:
привязки живут только в реестре, в сохранении `personaId` нет вообще. Поэтому утечка в экспорт, UI и рейтинг невозможна
по построению. Схема сохранения не менялась, добавились два необязательных поля:

- `profile.inherited` — опыт с ключами по `ownerId` этой кампании;
- `sunRaid.raids[].result.attackerOwnerIds` — кто летал в рейде: после возвращения флотов этого факта больше нигде нет.

`campaignId` выводится хешем из `personaSalt`. Копия слота — та же кампания, «Начать заново» — другая (новая соль).

**Что переносится** (`src/domain/npc/persona-registry.ts`):

| Данные | Как |
|---|---|
| Черты характера | дрейф ≤ 0,05 на черту за кампанию, только по фактам; темп зависит от `adaptability` |
| Сколько и когда играет | `propensity` и часовой пояс личности |
| Предпочтения | формула ADR §8.1, порог ≥ 3 эпизодов |
| Уроки | ≤ 16, с условием (раса противника), версиями боя и политики, числом эпизодов |
| Отношения | ≤ 16 направленных, по `personaId`: доверие, симпатия, обида, помощь полученная и оказанная, совместные операции |
| Итоги кампаний | ≤ 8 последних |

После смены версии боя вес уроков и предпочтений падает вдвое, после смены версии политики — умножается на 0,75.

Игрок в серии имеет один `p-player`: NPC помнят его помощь и нападения и под новым ником (решение 10).

**Не переносится:** флот, ресурсы, планеты, координаты, разведка, союзы, память кампании, обиды как `grudges`.
Отдельный тест проверяет, что карта и командование мира серии байт в байт равны карте чистого мира с тем же сидом.

**Свёртка.** Срабатывает при `campaignResult` — только после записи сохранения — и при «Закончить раунд серии».
Источники только подтверждённые: отчёты о боях, обиды, доставленная помощь (`aid_delivered`), совершённые рейды.
Намерения и «начал действие» не считаются. Повтор по `campaignId + outcomeVersion` ничего не меняет.

**Выборка при меньшем числе NPC.** 70% — жадно самые связанные с уже выбранными, 30% — случайные от соли новой кампании.
Если NPC больше, чем личностей, лишние играют новых персонажей и попадают в серию при свёртке.
Правило владельца от 24.10 (смесь активности и навыка при любом N) сохранено: шкалы пересобираются по слотам в порядке
личностей.

**Где опыт влияет на решения.** Всё читается из сохранения, реестр в кампании не открывается. Без `inherited` числа те же.

| Точка | Влияние |
|---|---|
| `weightNpcAction` | множитель `1 + 0,25·pref` |
| `npcRevengeIntensity` | старая обида, только к цели, которую NPC и так рассматривает |
| `chooseNpcAttackForce` (запас по силам) | урок по расе сдвигает порог не более чем на 0,05; решает всё равно отчёт разведки |
| Заявка в союз и ответ на заявку | доверие минус обида: сдвиг, а не решение |
| Выбор, кому помочь | небольшая прибавка за доверие |

| T-MEM-03 | повтор, перезагрузка и другой исход ничего не удваивают; один отчёт, записанный дважды, считается один раз |

**Electron:** `npm run test:npc-rounds-ui` — пройден локально, один сценарий, 6 NPC, одноразовый профиль:
мастер без серии → окно итога → реестр создан → повторный заход не меняет файл → «Новый раунд» → новый ник → мир серии,

**Регрессия:** файлы `test:npc`, `test:new-game` и `test:sun-raid`, 2 потока, BelowNormal: 265 тестов, 263 пройдено, 0 упало, 2 пропущено (длинные горизонты идут только на main и ночью). `tsc` и `test:inventory` чистые. Весь остальной набор и CI локально не запускались.

## Что не сделано и что важно знать

1. **Обучение не измерено.** Лабораторного сравнения «серия против чистой популяции» нет: подтверждено только, что опыт
   сохраняется и доходит до решений. Коэффициенты влияния (0,25; 0,05; 0,2; 0,15) — прототип, не баланс.
   Это работа для `bot-lab` в GitHub Actions; цифр до/после в этом отчёте нет.
2. **CPU не замерялся.** Шаг мира не менялся по сути: несколько чтений необязательного поля. Но бенчмарк 100 NPC не
   запускался, цель решения 11 в этом PR не подтверждена.
3. **Опыта пока мало.** Как и предупреждал ADR, G без этапа E переносит немного. Отчёты о боях и `aidEvents` усечены
   политикой хранения, уроки строятся по тому, что дожило до конца кампании. Обиды полные. `attackerOwnerIds` есть только
   у рейдов, завершённых после этого обновления.
4. **Статистика планов.** Свёртка читает `npcStrategy.outcomes`, если секция есть. На момент написания срез планов
   (`claude/npc-plans-slice`) ещё не в main, поэтому этот путь проверен только по типам, а не на реальной секции.
   Предпочтения по шаблонам в решения пока не подключены: нужно место выбора шаблона из среза.
5. **«Узнавание при контакте» упрощено.** ADR предлагал включать отношения при первом законном контакте. Сделано проще:
   отношение действует только там, где другой владелец уже законный кандидат. Новых знаний оно не даёт, но отдельного
   события «узнал» нет. Его логично добавить вместе с `RelationEdge` на этапе E.
6. **«Начать заново»** создаёт несвязанную кампанию: она не продолжает серию, при завершении основывает свою.
7. **Облако.** Свёртка выполняется на клиенте, когда он видит `campaignResult`. Сервер о реестре не знает. Реальный
   облачный сценарий не прогонялся: боевой сервер не трогали.
8. **Сброс серии вручную** (видение, этап G: «ручной reset для теста») в интерфейс не вынесен. Сейчас это удаление файла.
9. **Повторная свёртка по новым правилам.** Смена `PERSONA_OUTCOME_VERSION` разрешит свёртку той же кампании заново,
   но миграции накопленного для этого нет.

**Рисков для существующих сохранений не найдено:** новые поля необязательны, старые кампании при Вратах просто основывают
новую серию.
