## Фактически реализовано на данной стадии

1. src/domain/exploration/model.ts: таблицы 16 unique и 10 anomaly, коэффициенты q, специализации, риск, p12; основные расчёты P-based stage/catch-up, добывающая мощность транспортов/переработчиков, ограничение общего трюма, seeded chance, 30% материального груза.
2. src/domain/exploration/ledger.ts: отдельно тестируемые переходы владения/отзыва/выбивания, общий конечный запас, временные отметки, однонаправленная добыча, нормализация ledger и безопасная миграция старых сохранений.
3. src/domain/universe/runtime.ts и types.ts: startAt, канонический уникальный ID контакта для каждого появления, привязка 3 старых артов и 16 новых, 10 аномалий к профилям.
4. src/application/contracts.ts, persistence.ts: поле exploration хранится в основном SaveState, без второго localStorage. Старый save без поля получает пустую структуру.
5. src/domain/exploration/exploration.test.ts: инварианты расчётов, ID, видимость ±5 систем, запрет бесплатного debris без recycler, защита от дублирования запасов и срабатывания отзывов.
6. Команды npm run test:exploration, npm run balance:exploration:pr92 добавлены. Аналитическая баланс-матрица использует характеристики 3 рас, 7 уровней P, 26 профилей и различные флоты. Это **не симуляция настоящих PvE боёв**; боевые исходы и чистую прибыль не выдаёт за проверенные.

## Математика и ограничения

- Основное число P, stage = clamp((max(P,1000)/100000)^0.65, .15,15).
- B = round(100000 * stage * q). Catch-up выключен при менее 5 реальных score-профилях.
- rate = min(B*catch-up, .10*C_mine + .005*C_other), затем доля ресурса и оборонный boost. Debris добывается только при recycler.
- На контакт один общий запас round(B(worldScore,q)*lifeMinutes*1.5); количества неизменны при захвате и включают только указанную специализацию.
- Максимум 30% реально перевозимого материального cargo проигравшего; округление largest remainder, вместимость победителя — верхняя граница.
- Recall 30s, defense +10% на 120s, seeded reconnaissance 70%, 120s cooldown: тестируются только как domain правила, не как работающая UI-механика.
- p(t)=p12*min(1,t/12m)^1.5 при >=1m, но начисление жетонов не реализовано. 31 ремонтный жетон на каждую стартовую планету НЕ меняется.
- Военные силы, шанс победы и потери не симулируются. NPC попытки заданы только seeded функцией, не запуском флота.
