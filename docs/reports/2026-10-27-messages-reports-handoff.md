# Handoff: PR «Сообщения, отчёты и окно прогона» (аудит 26.10, PR 1)

Ветка `claude/messages-reports`, draft PR #111. Мерж решает владелец.

## Сделано
- **M1**: утечка воспроизведена тестом (`npc-missions.integration.test.ts`). Тосты маршрутизируются по адресату (`isFlightEventForPlayer`). Видимость входящих флотов на экране «Флоты» не тронута. Атака NPC на игрока больше не называется «Bot 01». В перенаселении, переработке и газе утечек нет: эти отчёты создаются только для планет игрока.
- **M2**: «Итог полёта» показывает имя планеты, исход по-русски, вернувшийся флот, добычу, доставленное или зачисленное и отдельно сгоревшее при переполнении склада (`cargoSettlement`). Для старых сохранений написано «данные недоступны». Из отчётов убраны технические id и ISO-даты. В интерфейсе каждая группа ресурсов («Добыча», «Зачислено», «Доставлено») идёт отдельной секцией; заголовок «Сгорело при переполнении склада».
- **M3**: бой без раундов показан как «ЗАХВАТ БЕЗ БОЯ: Планета захвачена без боя: обороны не было. Добыча: …».
- **M4**: модальное окно прогона и сводка мира `npcReplay.summary`. Бои считаются перед каждым прореживанием истории. Сводка переживает разбиение прогона и перезагрузку; старое сохранение посреди прогона помечается «неполная».
- **M5**: проверен `dist:win`, запуск `release/win-unpacked/Asterion.exe` с изолированным `--user-data-dir` (каталог `%APPDATA%\Asterion` владельца не изменился). Дерево процессов: главный, gpu, utility, renderer (4 шт.). CPU за 5 с: renderer 0,72 с, gpu 2,31 с, остальные 0. После закрытия окна все 4 процесса ушли за 0,5 с, через 5 с ни одного `Asterion.exe`. Дефект не воспроизведён, правок нет. Первый запуск исчез сам в течение 12 с; повторить не удалось, причина не установлена (возможно, окно закрыли вручную: игра открывается на весь экран).
