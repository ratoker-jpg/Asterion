# Asterion — система движения и визуальный язык компонентов

Единый источник правды для анимаций и поведения интерфейса. Новые экраны и
компоненты берут отсюда токены и рецепты, а не придумывают свои значения.

- Токены: `src/asterion-unified-theme.css` (`:root`, блок «Motion system»).
- Реализация: `src/motion.css` (подключается после всех стилей экранов, перед `final-polish.css`).
- Общий контракт интерфейса (типографика, радиусы, цвета): `DESIGN.md`.

## 1. Принципы

1. **Анимация объясняет, а не украшает.** Каждое движение отвечает на вопрос
   «что изменилось и откуда оно пришло»: обратная связь на нажатие, появление
   экрана, открытие окна, смена состояния.
2. **Частое не анимируется.** Тики ресурсов и таймеры, навигация по спискам,
   ввод текста, горячие клавиши — без анимации. Чем чаще действие, тем тише
   движение: кнопки нажимаются за 120 мс, экраны появляются за 280 мс, и только
   редкие сцены (главное меню, мастер новой игры, итог кампании) могут длиться
   дольше.
3. **Только `opacity` и отдельные свойства `translate` / `scale`.** Они не
   вызывают перерасчёт раскладки и идут на GPU. Отдельные свойства, в отличие от
   `transform`, *складываются* с уже заданными трансформациями: центрированием
   модалок `translate(-50%, -50%)`, парением планет, масштабом сцены. Анимировать
   `width/height/top/left/margin/padding` и `transform: scale(0)` запрещено.
4. **Появление — `ease-out`, никогда `ease-in`.** Объект быстро приходит и мягко
   останавливается; `ease-in` задерживает именно тот момент, на который смотрит игрок.
5. **Появления — только при монтировании, `animation-fill-mode: backwards`.** После
   окончания у элемента нет остаточной трансформации: геометрия, `position: fixed`
   потомков и замер длинной страницы (`GlobalPageScrollController`) не меняются.
   Контроллер перемеряет страницу по событию `animationend`.
6. **Повторный рендер не повторяет анимацию.** Анимация висит на элементе и
   проигрывается один раз, когда React его создаёт; обновления каждую секунду её
   не трогают.
7. **`prefers-reduced-motion` обязателен.** Остаются короткие затухания, исчезают
   все сдвиги, масштаб и фоновые циклы.

## 2. Токены

| Токен | Значение | Назначение |
| --- | --- | --- |
| `--ut-ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | появления, нажатия, всё по умолчанию |
| `--ut-ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | перемещение уже видимого объекта |
| `--ut-ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | выезжающие панели |
| `--ut-ease-hero` | `cubic-bezier(.22, 1, .36, 1)` | только меню и итог кампании |
| `--ut-motion-press` | 120 мс | нажатие кнопки |
| `--ut-motion-fast` | 160 мс | цвет/рамка при наведении, плитки флота |
| `--ut-motion-base` | 200 мс | вкладки, выделение пунктов меню |
| `--ut-motion-modal` | 240 мс | окна и их подложки |
| `--ut-motion-item` | 260 мс | карточки каталога |
| `--ut-motion-screen` | 280 мс | появление экрана или раздела |
| `--ut-stagger` | 40 мс | шаг между соседями при появлении |
| `--ut-rise` | 10 px | подъём экрана при появлении |
| `--ut-rise-small` | 6 px | подъём карточки |

## 3. Рецепты (`src/motion.css`)

| Ситуация | Как выглядит | Ключевой кадр |
| --- | --- | --- |
| Экран (маршрут, раздел «Флотов», интерьер здания, зона планеты) | поднимается на 10 px и проявляется с 35% за 280 мс; соседние панели идут с шагом 40 мс | `ut-screen-in` |
| Карта Вселенной | только проявление: пространственный экран, системы и планеты не сдвигаются | `ut-fade-in` |
| Боковое меню «Флотов» | въезжает слева на 16 px | `ut-slide-in-left` |
| Карточки каталога (корабли, оборона, ремонт, науки, Космодром, Солнца, рейтинг) | поднимаются на 6 px по очереди: первые 6 с шагом 40 мс, остальные вместе | `ut-item-in` |
| Плитки кораблей и миссий во «Флотах» (видны много раз в день) | то же, но 160 мс и шаг 20 мс | `ut-item-in` |
| Окно (подтверждение, план перелёта, Врата, рейд, корабль, отчёт, меню паузы) | подложка проявляется, панель вырастает из 96% от своего центра за 240 мс | `ut-fade-in` + `ut-pop-in` |
| Уведомление | выезжает снизу-слева за 200–250 мс | `runtimeToastIn` |
| Требует внимания (входящая атака) | класс `.ut-attention`: два спокойных пульса масштаба | `ut-attention` |
| Живой фон сцены | два слоя звёзд мерцают (6,5 и 9 с) и очень медленно дрейфуют (140 и 200 с) | `ut-twinkle`, `ut-drift` |

Чтобы новый экран получил появление, достаточно отрендерить его корнем внутри
`.workspace`, `.fleet-main-v1`, `.utility-screen-host` или
`.building-interior-host`. Чтобы карточки появлялись по очереди, их класс
добавляется в списки раздела 2 в `motion.css`, ничего больше не нужно.

## 4. Кнопки и интерактивные элементы

| Состояние | Поведение |
| --- | --- |
| Наведение (только мышь, `@media (hover: hover) and (pointer: fine)`) | цвет, рамка и фон меняются за 160 мс (`ease`). **Основные действия** дополнительно приподнимаются на 1 px и становятся на 8% ярче |
| Нажатие | любая включённая кнопка сжимается до 97% за 120 мс (`--ut-ease-out`); крупные объекты карты и участки зданий — до 99% |
| Фокус с клавиатуры | голубая обводка `--ut-focus` (2 px `--ut-accent`) со смещением 2–3 px |
| Выключена | без движения, прозрачность 0,4, курсор `not-allowed` |

Иерархия кнопок (цвета из `DESIGN.md`):

- **Основная** (одна на экран или окно: «Отправить», «Построить», «Объявить рейд», «Заказать уровень»): голубая заливка `--ut-accent` или цвет расы, белый текст 12 px с капсом и разрядкой .08–.12em, радиус `--ut-r-btn`. Список классов основных кнопок — в разделе 4 `motion.css`; новая основная кнопка добавляется туда.
- **Вторичная** («Отмена», «Мин./Макс.», переключатели): тёмная поверхность `--ut-surface-2`, рамка `--ut-border`, при наведении `--ut-border-strong`.
- **Опасная** (закрыть, удалить, отменить задание): красная `--ut-danger`; закрытие — красный крестик 18 px в зоне нажатия 40 px.
- **Плитка-переключатель** (миссии, разделы, фильтры): выбранная — заливка цвета расы слева направо и полоска 3 px слева (рецепт из `race-theme.css`).

## 5. Поверхности

- Панель экрана: `--ut-surface`, радиус `--ut-r-panel`, одна рамка `--ut-border`.
- Карточка внутри панели: `--ut-surface-2`, радиус `--ut-r-card`.
- Плашка-счётчик (В СТРОЮ, ДОСТУПНО, УРОВЕНЬ): ширина по содержимому с минимумом, внутренний отступ не меньше 12 px по горизонтали, текст никогда не касается рамки (см. `final-polish.css`).
- Строка статуса в карточке каталога — фиксированной высоты: заказ или блокировка не меняют высоту карточки (так устроены «Наука» и «Космодром»).

## 6. Раскладка и стабильность

- Сцена 1920×1080 всегда центрирована по `50vw` и стоит на одной высоте
  (`--asterion-stage-top`) — и в обычном режиме, и в режиме длинной страницы.
  Экраны не переключают режим длинной страницы сами: это делает только
  `GlobalPageScrollController`.
- Никаких захардкоженных высот страниц; никаких резервов под полосу прокрутки.
- Фон одинаковый в обоих режимах: звёздное небо — один кадр 1920×1080 в верхней
  части сцены, живой слой звёзд поверх.

## 7. Чек-лист для нового экрана или компонента

- [ ] Цвета, радиусы и длительности берутся из токенов `--ut-*`.
- [ ] Корень экрана рендерится внутри одного из контейнеров раздела 3, без собственной анимации появления.
- [ ] Если есть каталог карточек — их класс добавлен в списки появления.
- [ ] Основная кнопка добавлена в список основных действий (подъём при наведении).
- [ ] Окно использует пару «подложка + панель» из раздела 3.
- [ ] Ничего, что обновляется каждую секунду, не анимируется.
- [ ] Проверено с `prefers-reduced-motion: reduce`.
- [ ] Текст не касается рамок при больших числах (аудит на нагрузочном сохранении).
