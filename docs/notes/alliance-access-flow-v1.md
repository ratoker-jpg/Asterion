# Союзы: доступ к «Командованию», вступление и создание — v1

Статус: **gameplay/product contract** для дальнейшей реализации.

Этот документ фиксирует вход в союзную механику вокруг уже реализованного в PR #34 экрана `Командование`. Сам access/join/create flow в PR #34 пока **не реализован** и не должен считаться работающей runtime-механикой.

## 1. Предусловие: административное строение расы

Союзная механика становится доступна только после постройки соответствующего административного строения расы.

В Nemexia это не отдельная «Союзная палата». Референс использует три расовых здания:

- **Government** — Confederation;
- **Regulator Palace** — Terteths;
- **Hive** — Noxis.

Для Asterion точное собственное название/маппинг этих зданий в текущем коде ещё не зафиксированы. До отдельного решения нельзя молча придумывать одно общее название и считать его каноном.

### Контракт доступа

- Пункт `Командование` остаётся частью основной верхней навигации.
- Если нужное административное строение ещё не построено, содержимое `Командования` заблокировано.
- В lock-state игроку должно быть явно показано требование построить соответствующее административное строение.
- Наличие союза само по себе не должно обходить это требование.

## 2. Административное строение есть, но игрок/бот не состоит в союзе

При открытии `Командования` показывается **меню союзов**, а не полноценный союзный Command Center из PR #34.

В этом состоянии доступны два базовых пути:

1. **Вступить в существующий союз**.
2. **Создать свой союз**.

Минимальный состав списка существующих союзов:

| Поле | Что показываем |
| --- | --- |
| Союз | Название союза |
| Очки | Текущие очки/рейтинг союза |
| Участники | `N / 15` |
| Действие | `ВСТУПИТЬ` |

Кроме списка должна быть отдельная заметная команда `СОЗДАТЬ СОЮЗ`.

### Ограничение участников Asterion

- Максимум в одном союзе: **15 участников**.
- Люди и боты считаются одинаково и занимают один слот.
- При `15 / 15` вступление недоступно.
- Формула расчёта очков союза этим документом не определяется.

> В Nemexia-референсе исторический лимит другой; для Asterion каноническим продуктовым решением здесь является именно **15**.

## 3. Создание своего союза

Игрок/бот, который не состоит в союзе и имеет требуемое административное строение, может вместо вступления создать собственный союз.

Минимально подтверждённые настройки при создании:

- **название союза**;
- **герб / эмблема союза** — игрок должен иметь возможность выбрать визуальный знак союза.

Также интерфейс создания может в дальнейшем содержать дополнительные параметры союза, но конкретный состав этих полей этим контрактом пока **не зафиксирован**. Их нельзя придумывать как обязательный канон без отдельного решения.

Базовый create-flow:

1. Игрок/бот открывает `Командование`.
2. Игра проверяет административное строение.
3. Если субъект не состоит в союзе, показывается меню союзов.
4. Субъект нажимает `СОЗДАТЬ СОЮЗ`.
5. Открывается форма создания.
6. Субъект задаёт название и выбирает герб/эмблему.
7. После успешного создания новый союз становится текущим союзом создателя.
8. Создатель входит в него как первый участник, поэтому состояние участников начинается с `1 / 15`.
9. После создания открывается полноценный экран `Командование` из PR #34 уже для нового союза.

Роль/права создателя, должность лидера, передача лидерства, стоимость создания, требования к уникальности названия, доступный набор гербов и возможность загрузки собственного изображения этим документом пока **не определены**.

## 4. Вступление в существующий союз

Базовый join-flow:

1. Игрок/бот открывает `Командование`.
2. Игра проверяет наличие требуемого административного строения.
3. Если строения нет — показывается lock-state.
4. Если строение есть, но субъект не состоит в союзе — открывается меню союзов.
5. Субъект выбирает доступный союз и нажимает `ВСТУПИТЬ`.
6. Если в союзе меньше 15 участников, membership-state меняется на «состоит в союзе».
7. После успешного вступления открывается полноценный экран `Командование`, реализованный в PR #34.

Механика заявок, ручного одобрения лидером, приглашений, выхода, исключения и cooldown после выхода этим контрактом **не определена**. Их нельзя добавлять как факт без отдельного решения.

## 5. Игрок/бот уже состоит в союзе

Если административное строение построено и субъект уже состоит в союзе, `Командование` открывает существующий полноценный союзный интерфейс PR #34:

- `ОБЗОР СОЮЗА`;
- `УЧАСТНИКИ`;
- `ЗАПРОСЫ РЕСУРСОВ`;
- `ДИПЛОМАТИЯ`;
- `СОВМЕСТНЫЕ ОПЕРАЦИИ`;
- `НАСТРОЙКИ СОЮЗА`;
- `Рейд на Солнце` как флагманская совместная цель.

## 6. State machine

```text
Командование
    |
    v
[Есть нужное административное строение?]
    | нет
    +----> LOCK: требуется строение
    |
   да
    v
[Состоит в союзе?]
    | нет
    +----> МЕНЮ СОЮЗОВ
    |          |
    |          +--> ВСТУПИТЬ В СУЩЕСТВУЮЩИЙ
    |          |        |
    |          |        +--> выбрать союз
    |          |        +--> проверить N < 15
    |          |        +--> membership = joined
    |          |
    |          +--> СОЗДАТЬ СОЮЗ
    |                   |
    |                   +--> название
    |                   +--> герб / эмблема
    |                   +--> создать союз
    |                   +--> creator = first member (1 / 15)
    |                   +--> membership = joined
    |                            |
    +----------------------------+
                                 v
                        FULL COMMAND CENTER
                           (PR #34)
```

## 7. Что является продуктовым решением Asterion

Зафиксировано:

- доступ к союзной механике требует административного строения;
- без membership после разблокировки показывается меню союзов;
- в меню доступны два пути: вступить в существующий союз или создать свой;
- в списке союзов обязательны название, очки, участники и действие вступления;
- лимит союза — **15** участников суммарно, включая ботов;
- при создании союза обязательно задаются **название** и **герб / эмблема**;
- создатель становится первым участником нового союза (`1 / 15`);
- после вступления или создания открывается полноценный Command Center из PR #34.

Не зафиксировано и остаётся отдельной задачей:

- собственные названия административных зданий Asterion для трёх рас;
- дополнительные поля формы создания союза;
- стоимость и дополнительные требования к созданию;
- правила уникальности/валидации названия;
- набор и редактор гербов, возможность пользовательской загрузки изображения;
- роль/права создателя и система лидерства;
- заявки и подтверждение вступления;
- приглашения;
- выход/исключение/cooldown;
- расчёт очков союза;
- backend/multiplayer sync и конкурентное занятие последнего 15-го слота.

## 8. Implementation boundary для PR #34

PR #34 сейчас реализует **только состояние после вступления/создания** — полноценный Command Center и локальные foundation-flow внутри него.

Этот документ не означает, что следующие механики уже существуют в runtime:

- проверка административного строения;
- lock-state `Командования`;
- каталог союзов;
- membership-state;
- реальное вступление;
- создание союза;
- выбор и сохранение герба;
- enforcement лимита 15.

Они должны быть реализованы отдельным последующим изменением с миграцией save-state и тестами, а не имитироваться UI-кнопками без доменной логики.
