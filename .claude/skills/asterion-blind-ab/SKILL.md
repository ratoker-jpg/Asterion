# Слепое A/B для Asterion

Адаптация «gauntlet» из studioigor-skill
(https://github.com/studioigor/studioigor-skill, лицензия MIT, автор studioigor).
Взяты идеи: слепое сравнение, вердикт до раскрытия, один главный разрыв за раунд.
Скрипт `ab.cjs` написан заново на Node (работает на Windows); скрипты оригинала не использовались.

## Зачем

Когда агент сам оценивает свою правку, он оценивает мягко («я так и задумывал»).
Слепое сравнение это убирает: смотришь два кадра, не зная, какой «до», какой «после».

## Когда применять

Только для того, на чём держится впечатление: ключевые экраны, первая минута
(`asterion-first-minute`), ощущение боя, шапка, герб. Не для мелких правок и не для
каждого PR: там хватает кадров «до/после» в описании.

## Шаги раунда

1. **Кадры.** Взять с CI кадры «до» (main) и «после» (ветка), снятые одним сценарием
   `electron/visual-*.cjs`: одинаковые размеры, сид и состояние. Сложить в две папки
   с одинаковыми именами файлов: `before/` и `after/` (вне репозитория или в
   `visual-qa/ab/`, в git не коммитить).
2. **Перемешать:**
   ```bash
   node .claude/skills/asterion-blind-ab/ab.cjs before after --out ab-round-01
   ```
   Появятся `ab-round-01/A/`, `ab-round-01/B/` и `key.json`. Файлы получают нейтральные
   имена (`01.png`, `02.png`), сторона каждой пары выбирается случайно. **Не открывать
   `key.json`**, не смотреть размеры и даты файлов.
3. **Вердикт до раскрытия.** Создать `ab-round-01/verdict.md`:
   ```markdown
   # Раунд 01 — <экран>
   КРИТЕРИЙ следующее действие: A — почему, одной фразой
   КРИТЕРИЙ читаемость текста: B — почему
   ГЛАВНЫЙ РАЗРЫВ: <одно наблюдаемое отличие, не чувство>
   ```
   Критерии выбрать заранее, 3–4: понятно ли следующее действие; читаемость текста;
   иерархия (что видно первым); стиль и единство; отклик (по кадрам). Значение:
   `A`, `B` или `ничья`. Пока нельзя показать, чем именно выигрывает «после», выигрывает «до».
4. **Раскрыть:**
   ```bash
   node .claude/skills/asterion-blind-ab/ab.cjs --reveal ab-round-01
   ```
   Скрипт не откроет ключ, пока в `verdict.md` нет хотя бы одной строки `КРИТЕРИЙ` и
   ровно одной строки `ГЛАВНЫЙ РАЗРЫВ`. Он покажет, где было «до», где «после», и итог.
5. **Если выиграло «после».** Перечитать критерий: ты сам делал эту сторону и мог её
   узнать. Если причину не подтвердить кадром, считать победой «до».
6. **Дальше.** Один главный разрыв = одна правка в следующем круге. Остальное в «потом».
7. В описание PR: что сравнивали, кто выиграл по каждому критерию, главный разрыв.
   Последнее слово всё равно за владельцем.

## Самопроверка скрипта

```bash
node .claude/skills/asterion-blind-ab/ab.cjs --self-check
```
Создаёт две временные папки с крошечными файлами, прогоняет перемешивание и раскрытие,
проверяет, что ключ сходится, что раскрытие без вердикта отказывает, и всё удаляет.
Запускать после любых правок скрипта.

## Чего не делать

- Не сравнивать разные размеры и разные состояния игры: разница выдаст сторону.
- Не менять сценарий съёмки между раундами.
- Не править несколько вещей за раунд: потом не понять, что помогло.
- Не запускать на каждом PR.
